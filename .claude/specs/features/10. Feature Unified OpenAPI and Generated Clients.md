# Feature: Unified OpenAPI and Generated Clients

**Target:** `src/*/routes/swagger/docs.json`, `index.js`, new `src/shared/utils/openapi.js`
**Priority:** P1 · **Effort:** S–M · **Status:** Partly done (2026-11-13). `GET /services/api/openapi.json` merges the mounted services into one OpenAPI 3.1 document: absolute paths, service tags, unique operation ids, one name per security scheme, every `$ref` resolved. Routes with no documented operation get a generated stub marked `x-undocumented`. Drift check: the documents describe every route they cover (0 documented-only), and `tests/unit/openapi/undocumentedRoutes.baseline.json` lists the 161 routes still without a description. That list is a ratchet: new undocumented routes fail the test, and documenting a route means removing it from the list. Not done: the `validate()` schema export, a docs page, the typed client generator (in feature 09), a schema-validator run in CI (no OpenAPI validator is a dependency yet), and writing the 161 descriptions.

## Problem

Each service ships its own Swagger document (`routes/swagger/docs.json`) and the service template renders it. There is no single document for the whole app, so engineers can't import one spec into Postman, Bruno or Insomnia, generate one client, or give one spec to an AI agent. The documents are hand-written, so they drift from the routes. The steering docs had several wrong paths until 2026-11-12, for example dataservice CRUD and workflow run endpoints.

## Goal

One accurate OpenAPI 3.1 document per running app, and typed clients generated from it.

## Proposal

- `GET /services/api/openapi.json` (and `.yaml`): merges the docs of every **instantiated** service and instance, tags operations by service, and includes the security schemes the app actually uses (API key header, bearer personal access token, session cookie).
- A Swagger UI or Scalar page at `/services/api/docs`, served from local assets (CSP stays strict).
- **Drift check:** a Jest test loads each service, lists the routes Express registered, and fails when a route has no OpenAPI operation or an operation has no route.
- **Schemas from validation:** routes that use `validate({ body, query, params })` export those schemas into the document, so request bodies are documented once.
- **Clients:** `nooblyjs openapi --client ts` writes a dependency-free typed `fetch` client (`client.caching.put(key, value)`), plus a `.http` collection. Other languages through the standard `openapi-generator`.
- The browser client libraries (`src/*/scripts/js/index.js`) can later be generated from the same document.

## Work breakdown

1. Merge function and the two endpoints; tags and security schemes.
2. Route ↔ operation drift test; fix the gaps it finds.
3. Export `validate()` schemas into the document.
4. Docs page with local assets.
5. TypeScript client generator in the CLI (feature 09).

## Acceptance criteria

- The merged document validates against the OpenAPI 3.1 schema.
- The drift test passes for every service.
- The generated TypeScript client compiles with `strict` and can call `caching` put/get against a running app in an integration test.

## Risks

- **Large first diff.** The drift test will surface many missing operations; land it as a warning first, then make it fail.
