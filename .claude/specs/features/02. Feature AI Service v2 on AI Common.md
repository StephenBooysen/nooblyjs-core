# Feature: AI Service v2 on nooblyjs-ai-common

**Target:** `src/aiservice`
**Priority:** P0 · **Effort:** M · **Status:** Partly done (2026-11-13). Bridge to the shared module with `prompt` (legacy shape), `complete`, `stream`, `streamToResponse`, `generateObject` and budgets; new provider names `anthropic`, `openai-compatible`, `bedrock`, `vertex`, `azure`, `mock`; REST `complete`, `stream`, `generate-object`, `embed` (501 for now). Still open: `embed()` in the shared module, legacy providers not removed, no dashboard playground, no manual checks against live providers (no keys here), semantic search not moved.

## Problem

The repo has two AI layers that don't meet:

- `src/aiservice/provider/` (CommonJS): one class per provider (`aiclaude.js`, `aiopenai.js`, `aiollama.js`, `gemini.js`, `aiopenaikv.js`, `aitensorflow.js`), each wrapping its own SDK. The base class `aibase.js` offers only `prompt(prompt, options)`, plus token tracking and cost estimates.
- `src/aiservice/common/` (`nooblyjs-ai-common`, ESM, no dependencies): `stream()` and `complete()` for Anthropic, OpenAI (Chat and Responses), OpenAI-compatible, Bedrock, Vertex, Azure and a mock, with tool calls, prompt-cache-aware system text, a model catalogue with prices, retry and SSE. The NooblyJS AI host apps already use it.

So an engineer using `serviceRegistry.aiservice()` gets the weaker layer: no streaming to the browser, no tool calls, no structured output and no embeddings. Semantic search Phase 2 (`.claude/steering/features/01…`) is blocked because no AI provider has `embed()`.

## Goal

`aiservice` becomes a thin CommonJS service over `nooblyjs-ai-common`. One API for every provider, with the features engineers reach for today.

## Proposal

### API

```javascript
const ai = serviceRegistry.aiservice('anthropic', { model: 'claude-sonnet-5-5' });

// Unchanged: existing callers keep working
const text = await ai.prompt('Summarise this ticket', { maxTokens: 300 });

// New
const result = await ai.complete({ system, messages, tools, maxTokens });   // { text, toolCalls, usage, cost }
for await (const event of ai.stream({ messages })) { /* text, tool_use, usage */ }
ai.streamToResponse(res, { messages });                                      // SSE via common's openSSE
const data = await ai.generateObject({ messages, schema });                  // JSON validated against a schema
const vectors = await ai.embed(['text one', 'text two'], { dimensions: 768 });
```

### Providers

Provider names follow the common catalogue: `anthropic` (alias `claude`), `openai` (alias `chatgpt`), `openai-compatible`, `ollama`, `gemini`, `bedrock`, `vertex`, `azure`, `mock`. Keep `openai-kv` (Key Vault auth) as a credentials option on `azure`. Move `tensorflow` to an optional, separately documented provider; it is not an LLM client.

The memory-style default for tests is `mock`, so `serviceRegistry.aiservice('mock')` works with no keys.

### Embeddings

Add `embed()` to common's provider layer for OpenAI, Ollama (`/api/embed`), Gemini, Bedrock (Titan/Cohere) and Vertex. Anthropic has no embeddings endpoint: throw a clear `ApiError` naming the alternatives. This completes the `aiservice` backend that `src/searching/modules/embeddings.js` already expects.

### REST and dashboard

- `POST /services/aiservice/api/complete`, `POST /api/stream` (SSE), `POST /api/embed`, `GET /api/models` (from the catalogue and discovery).
- Dashboard: a playground (model picker, system prompt, streaming output, tokens and cost per call), and usage over time per model.

### Cost and limits

Use common's `priceUsage` and `costOf`. Add per-instance budgets (`maxCostPerDay`, `maxTokensPerRequest`) that throw `ClientError(429)` when exceeded, and emit `ai:usage` events for the measuring service.

## Work breakdown

1. A CommonJS bridge: load the ESM package with dynamic `import()` once and cache it. The ESM package keeps zero dependencies.
2. New `providers/aiCommon.js` implementing `prompt`, `complete`, `stream`, `generateObject`, `embed`. Map existing provider names to catalogue providers.
3. Keep the old provider classes behind `legacy: true` for one minor release, then remove them and their SDK dependencies (`@anthropic-ai/sdk`, `openai`).
4. `embed()` in common (separate PR in `src/aiservice/common`, with contract tests for every provider).
5. Routes, Swagger and the dashboard playground.
6. Update semantic search to Phase 2 using `ai.embed()`.

## Acceptance criteria

- Every existing `ai.prompt()` call and test passes unchanged.
- `complete`, `stream`, `generateObject` and `embed` pass the common contract suite against the mock, and a manual check against at least Anthropic, OpenAI and Ollama.
- Streaming reaches a browser through `streamToResponse` with no buffering.
- Removing the legacy providers drops at least two SDK packages from `dependencies`.

## Risks

- **ESM from CommonJS.** Dynamic `import()` makes the first call async. The factory already returns a service whose methods are async, so callers don't notice.
- **Behaviour drift.** Token counts and costs will change slightly. Note it in the changelog.
