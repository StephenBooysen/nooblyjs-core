# Feature: Express 5, ESM and a Node 22 Baseline

**Target:** `package.json`, `index.js`, all `routes/index.js`
**Priority:** P2 · **Effort:** M · **Status:** Proposed (2026-11-12)
**Depends on:** 08 (types, for the `exports` map), 11 (contract tests, as a safety net)

## Problem

- `express` is `^4.19.2`. Express 5 is the current major, with native async error handling and stricter path syntax. The registry is partly prepared: `src/shared/utils/routePattern.js` exists so routes mount on Express 5, but only the working, searching, filing and workflow routes use it.
- `engines.node` says `>=18`, while the Dockerfile uses Node 24 and CI tests Node 22 and 24. Node 18 has reached end of life, so the declared support is wider than what is tested.
- The package is CommonJS only. ESM apps can import it, but get no named exports and no tree-shaking. The NooblyJS AI host and `nooblyjs-ai-common` are ESM.
- `express-async-errors` and `body-parser` patch around Express 4 behaviour that Express 5 makes unnecessary.

## Goal

The registry mounts on Express 4 and 5, the package works natively from ESM and CommonJS, and the supported Node versions match what CI tests.

## Proposal

1. **Node baseline:** set `engines.node` to `>=22`, document it, and use built-ins where they replace dependencies (`fetch` instead of `node-fetch`, `node:test` already used by common).
2. **Express 5 compatibility:** wrap every wildcard or optional-parameter route with `route()`; run the Jest suite and the Playwright smoke test against both Express 4 and 5 in CI (a matrix variable that installs the chosen version).
3. **Drop shims when on Express 5:** native promise rejection handling replaces `express-async-errors`; `express.json()` replaces `body-parser`.
4. **Dual package:** add an `exports` map with `import` and `require` conditions. The ESM entry re-exports the singleton and named helpers (`ClientError`, `sendSafeError`, `validate`, `route`, `FsStore`, `createShell`), so ESM apps write `import registry, { ClientError } from 'nooblyjs-core'`. Keep one singleton across both entries.
5. **Public subpaths:** `nooblyjs-core/testing` (feature 11), `nooblyjs-core/ai` (re-export of `nooblyjs-ai-common`), `nooblyjs-core/store`, `nooblyjs-core/shell`.

## Acceptance criteria

- CI matrix passes for Express 4 and 5 on Node 22 and 24.
- An ESM sample app and a CommonJS sample app get the same registry instance when both load the package in one process.
- `node-fetch`, `body-parser` and `express-async-errors` are removed from `dependencies` (or kept only for Express 4 users, documented).

## Risks

- **Breaking change for Node 18/20 users.** Ship as a minor with a clear note, since those versions are out of support, or as part of a 2.0 release together with the removal of legacy AI providers (feature 02).
