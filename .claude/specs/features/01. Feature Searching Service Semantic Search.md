# Feature: Searching Service Semantic Search (phases 2–4)

**Target:** `src/searching` (vector provider, `GET /services/searching/api/semantic`, dashboard Match option)
**Priority:** P1 · **Effort:** M · **Status:** Partly done (2026-11-13)

This file was missing from the repo; the roadmap linked to it. It was written from the roadmap row ("Real embeddings, semantic HTTP routes and UI"), and the phase split below is the scope chosen for that row. Change it if the original phases were different.

## Phases

| Phase | Scope | State |
|---|---|---|
| 1 | Vector provider: hash embeddings by default, background embedding queue, hybrid ranking | Done before this work |
| 2 | Meaning search over HTTP (`semantic` route, `hybrid` or `semantic` mode) | Done (2026-11-13) |
| 3 | Real embeddings through the AI service (`embedding.backend: 'aiservice'`), tested with a stub that maps related words to one vector | Done (2026-11-13), tested with a stub, not a live provider |
| 4 | Dashboard Match option (Keywords, hybrid, semantic) and UI tests | Done (2026-11-13) |

## Behaviour

- `GET /services/searching/api/semantic?query=…&index=…&mode=hybrid|semantic&limit=…` returns `{ success, mode, data }`. Other providers answer 400 with a message.
- The `aiservice` backend calls `embed(texts, { model, dimensions })` on the AI service and reads `vectors`.
- A failed embedding leaves the documents searchable by keyword. `lastEmbedError` records why.

## Known gaps

- A failed embedding still emits `search:embed:complete` with `vectors: 0`. It should emit an error event. Tests pin the current behaviour.
- No live-provider check: embeddings were tested with a stub.
- No retrieval-quality evaluation for search. `evaluateRetrieval()` in the knowledge service works on any object with `retrieve()`, so it could be generalised.

## Tests

- `tests/unit/searching/meaningSearch.test.js`: meaning match without a shared keyword, hybrid ordering, batching to the AI service, failure handling.
- `tests/unit/searching/semanticRoute.test.js`: the route's modes, the 400 on other providers, input limits.
- `tests/ui/searchingMode.spec.js`: the Match option sends the search to the right route.
