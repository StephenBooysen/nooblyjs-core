# Feature: Test Kit and Provider Contract Tests

**Target:** new `src/testing/` (exported as `nooblyjs-core/testing`), `tests/contract/`
**Priority:** P1 · **Effort:** M · **Status:** Proposed (2026-11-12)

## Problem

- **For app teams:** testing code that uses NooblyJS means repeating registry setup and teardown, Express and emitter creation, temp directories, and cleanup of timers so Jest's `detectOpenHandles` stays quiet. Each team rediscovers this.
- **For core:** providers of the same service are supposed to behave the same, but parity is tested ad hoc per provider. Redis, Memcached, S3 and filing suites are disabled (`*.disabled.js`) because they need live infrastructure, so drift between memory and real backends goes unnoticed. Coverage is ratcheted at 51% statements.

## Goal

A test kit that makes app tests a few lines, and one contract suite per service that every provider must pass, runnable against real backends in containers.

## Proposal

### Test kit

```javascript
const { createTestRegistry } = require('nooblyjs-core/testing');

let t;
beforeEach(async () => { t = await createTestRegistry({ services: ['caching', 'dataservice'] }); });
afterEach(() => t.cleanup());            // reset registry, timers, temp dirs, listeners

it('caches orders', async () => {
  const cache = t.registry.cache('memory');
  await cache.put('k', 1);
  expect(t.events).toHaveEmitted('cache:put:default', { key: 'k' });
});
```

Includes: temp directories under `.temp/tests/data/`, a fake clock for scheduling, workflow and queue delays, an event recorder with Jest matchers, `t.request` (supertest against the app with an API key already set), and the `mock` AI provider with scripted responses and tool calls.

### Contract tests

`tests/contract/{service}.contract.js` exports a suite that takes a provider factory:

```javascript
runCacheContract('redis', () => registry.cache('redis', { redisurl: process.env.REDIS_URL }));
```

- Suites for caching, queueing (including feature 06's retry/DLQ semantics), dataservice, filing, searching, authservice and aiservice.
- Memory providers run in the normal `npm test`.
- `npm run test:contract` runs the real backends with Testcontainers or a `docker-compose.test.yml` (Redis, Memcached, MongoDB, RabbitMQ, MinIO for S3, a local Git remote). CI runs it in a separate job.
- This replaces most `*.disabled.js` suites.

## Work breakdown

1. `createTestRegistry`, cleanup, event matchers, fake clock.
2. Contract suites for caching and queueing; run memory + Redis in CI.
3. dataservice (memory, file, MongoDB), filing (local, S3 via MinIO, git), searching.
4. authservice and aiservice (mock) suites.
5. Raise the coverage threshold as suites land.

## Acceptance criteria

- The existing unit tests for two services are rewritten with the kit and are shorter, with no open-handle warnings.
- Memory and Redis cache providers pass the same contract suite.
- The contract CI job runs in under 10 minutes.

## Risks

- **CI time and flakiness with containers.** Separate job, retries only at the container start step, never on assertions.
