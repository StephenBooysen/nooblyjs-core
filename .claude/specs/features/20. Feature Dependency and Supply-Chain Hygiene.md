# Feature: Dependency and Supply-Chain Hygiene

**Target:** `package.json`, `package-lock.json`, `.github/workflows/`, `scripts/`
**Priority:** P0 (fix advisories) / P1 (automation) · **Effort:** S + M · **Status:** Done (Phase 0 and Phase 1, 2026-11-13). Nightly audit, Renovate, provenance with an SBOM, and cloud SDKs as optional peers (a production install has none). Not yet proven: the nightly job has not run on GitHub.
**Fixes:** H-2 in `../go-to-market/PRODUCTION_READINESS_REVIEW_2026-11-12.md`

## Problem

On 2026-09-29, `npm audit --omit=dev` reported zero advisories. On 2026-11-12 it reports 21 (8 high, 3 critical); a full-tree audit reports 32. Nothing in the code got worse: new advisories were published against existing dependencies. The CI gate only runs on pushes and pull requests, so the regression went unseen.

Notable entries:

- `simple-git` (critical): command execution through Git configuration. The git filing provider uses it.
- `proxy-addr` (critical): IP spoofing with trusted subnets. This affects `TRUST_PROXY` and the per-IP login rate limiter.
- `@azure/msal-node` and `@azure/identity`, `@grpc/grpc-js`, `body-parser`, `brace-expansion`, `follow-redirects`, `multer`, `node-forge` (high).

The list of abandoned packages from May still stands: `ftp`, `stompit`, `pdf-parse@1.x`, `@google-cloud/storage@5`.

## Goal

No known high or critical advisories in production, new advisories are noticed within a day, and the package ships with provenance.

## Proposal

### Fix now

1. `npm audit fix` for the non-breaking upgrades. Run the full suite, the Playwright tests and the git filing tests.
2. `simple-git` 3 → 4: review the breaking changes against `filingGit.js`, upgrade, and run the git provider against a local bare repository.
3. Confirm `proxy-addr` is fixed through the Express upgrade it ships with. Add a test that the login rate limiter keys on the right client IP behind `TRUST_PROXY`.
4. Update `DEPENDENCY_STATUS.md` and the remediation tracker.

### Keep it fixed

- **Scheduled audit:** a nightly CI job runs `npm audit --omit=dev --audit-level=high` on `main` and opens an issue on failure.
- **Automated updates:** Dependabot or Renovate, grouped weekly for minor and patch versions, with auto-merge when CI is green.
- **Replace abandoned packages:** `ftp` → `basic-ftp`; `stompit` → a maintained STOMP client, or drop ActiveMQ STOMP if unused; `@google-cloud/storage` 5 → 7; `pdf-parse` → 2.x or `pdfjs-dist`.
- **Trim the tree:** move cloud SDKs (`@aws-sdk/*`, `@azure/*`, `@google-cloud/*`, `amqplib`, `memjs`, `mongodb`, `stompit`) to optional peer dependencies, loaded only when their provider is chosen. Most apps then ship a fraction of today's dependency tree and attack surface.
- **Provenance and SBOM:** publish with `npm publish --provenance`, and generate a CycloneDX SBOM in CI as a release artefact.
- **Doctor:** `nooblyjs doctor` (feature 09) runs the audit locally.

## Acceptance criteria

- `npm audit --omit=dev --audit-level=high` passes, and CI is green.
- A nightly audit job exists and has run at least once.
- A fresh `npm install nooblyjs-core` without optional peers installs no cloud SDKs.

## Risks

- **Major upgrades (simple-git 4, GCS 7)** need provider regression tests; feature 11 provides the contract suites.
