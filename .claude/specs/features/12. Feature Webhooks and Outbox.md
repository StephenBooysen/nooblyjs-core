# Feature: Webhooks and Transactional Outbox

**Target:** `src/notifying` (outbound webhooks), `src/dataservice` (outbox)
**Priority:** P2 · **Effort:** M · **Status:** Proposed (2026-11-12)
**Depends on:** 06 (Reliable Jobs)

## Problem

Integration with other systems is most of a backend engineer's work. NooblyJS emits rich events on an in-process EventEmitter and has a notifying service for topics, but nothing delivers events to other systems reliably:

- No outbound webhooks with signing, retries and a delivery log.
- No inbound webhook verification helper (Stripe, GitHub and Slack style signatures).
- Writing a record and publishing an event are two separate steps, so a crash between them loses the event (the dual-write problem).

## Goal

Reliable, signed, observable event delivery in and out of a NooblyJS app.

## Proposal

### Outbound webhooks

```javascript
const hooks = serviceRegistry.notifying('default');
await hooks.subscribeWebhook({
  url: 'https://partner.example.com/hooks',
  events: ['order.created', 'order.paid'],
  secret: 'whsec_…',                 // HMAC-SHA256 signature header
});
await hooks.publish('order.created', { orderId });
```

- Delivery through the reliable queue (feature 06): exponential backoff, a dead-letter list, and automatic disabling of endpoints that keep failing.
- Signed with a timestamped HMAC header (`NooblyJS-Signature: t=…,v1=…`) to stop replays.
- The SSRF guard from the fetching service applies to webhook URLs (no private addresses unless allowed).
- Dashboard: subscriptions, delivery log with request/response, redeliver button.

### Inbound verification

`verifyWebhook(req, { provider: 'stripe' | 'github' | 'slack' | 'nooblyjs', secret })` as Express middleware, with raw-body capture and constant-time comparison.

### Transactional outbox

`dataStore.addWithEvent(container, record, event)` writes the record and an outbox entry together (one document in MongoDB, one transaction where the provider supports it, one atomic file write for the file provider). A relay moves outbox entries to the queue/webhooks and marks them sent.

## Acceptance criteria

- A failing endpoint receives retries with backoff and lands in the dead-letter list after the configured attempts.
- Signatures verify with the published algorithm; replays outside the tolerance window are rejected.
- Killing the process between write and publish does not lose the event (outbox test with the file provider).

## Risks

- **Secrets storage.** Webhook secrets live in the settings service (encrypted).
