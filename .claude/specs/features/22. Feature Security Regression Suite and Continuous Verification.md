# Feature: Security Regression Suite and Continuous Verification

**Target:** `tests/unit/security/`, `tests/ui/`, `.github/workflows/ci.yml`, `src/aiservice/provider/aibase.js`
**Priority:** P1 · **Effort:** M · **Status:** Done, Phase 0 (2026-11-13)
**Fixes:** L-2; prevents regressions of C-1, C-2, H-1, H-3 in `../go-to-market/PRODUCTION_READINESS_REVIEW_2026-11-12.md`

## Problem

The suite is strong on unit behaviour (2,228 passing tests, plus dedicated SSRF, traversal, brute-force and listener-leak tests), and the September live probe passed 70/70 checks. But the critical issues found on 2026-11-12 were all **cross-cutting authorization** problems: which credential can reach which route, and how exemptions in one guard interact with another. No test looks at that, so every check passed while an anonymous visitor could read server files.

Also, the Jest run writes `.application/data/ai-tokens.json` outside `.temp/`, because `aibase.js` defaults its token log to `process.cwd()`.

## Goal

The security properties the product depends on are tested on every pull request and probed against a running build.

## Proposal

### 1. Exploit-chain regression tests

Turn the review reproduction (`.temp/tests/review-2026-11-12/repro-invite-to-filing.js`) into permanent Jest tests in `tests/unit/security/`:

- Anonymous users can't obtain a usable invitation code in the default mode (feature 16).
- A `user` can't change filing settings, and no request can read outside the filing root (feature 15).
- HTML and SVG uploads are never served inline (feature 17).
- `working/run`, scheduling and workflow routes reject absolute and traversal paths (feature 18).

### 2. Authorization matrix

A table-driven test that boots the app as in `app.js` (with temp directories), enumerates every registered Express route, and calls each one as anonymous, `user`, `admin`, a scoped key and an unscoped key. The expected status comes from each route's declared permission (feature 19). Any new route without a declaration fails the test.

### 3. Dynamic scan in CI

- An OWASP ZAP baseline scan against the Playwright-started server, failing on high-risk alerts.
- Secret scanning (gitleaks) on every push.

### 4. Live production probe

Fold the 70 September checks into a script (`npm run probe -- --url https://…`) that operations can run against staging and production after each deploy. Add the new checks above to it.

### 5. Test hygiene

- `aibase.js`: default the token log under the configured `dataDir`, and in tests under `testDataDir()`. No test may create files outside `.temp/`.
- A Jest global teardown that fails the run if `.application/` or other non-`.temp` paths were created during it.

## Acceptance criteria

- The four exploit-chain tests fail on the code as of 2026-11-12 and pass once features 15–18 are done.
- The authorization matrix covers every `/services/*/api` route.
- A full `npm test` leaves no files outside `.temp/`.
- ZAP baseline and gitleaks run in CI.

## Risks

- **Matrix maintenance.** It is generated from route metadata, so it grows with the API automatically.
