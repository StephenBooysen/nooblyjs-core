# Roadmap: Engineering Acceleration

**Drafted:** 2026-11-12
**Purpose:** Make NooblyJS Core the fastest way for an engineer, or an engineer working with an AI coding agent, to go from an idea to a production Node.js service.

## Where the product stands

NooblyJS Core already gives a team a lot that usually takes weeks to assemble: 16 services behind one registry, pluggable providers (memory to Redis to AWS/Azure/GCP), a REST API and dashboard per service, auth with tokens and invitations, workflows with schedules, a hardened production setup (CSP, helmet, rate limiting, safe errors, health probes, Docker, CI).

Its gaps sit in three places:

1. **AI-era development.** Engineers now build with coding agents and ship AI features. The modern AI layer (`src/aiservice/common`: streaming, tool calls, every major provider, cost) is not what `aiservice` uses. `aiservice` still wraps one SDK per provider and only offers `prompt()`. There is no embedding call, so semantic search is stuck at Phase 2. There is no way for a coding agent to see or drive a running NooblyJS app.
2. **Developer experience.** No TypeScript types, no CLI, no single OpenAPI document, and API names that are easy to guess wrong. The steering usage guides documented `cache.set`, `queue.process` and `dataService.create` for months, none of which exist. That is a signal: the API should either match what people expect or the tooling should make the real API discoverable.
3. **Production primitives engineers expect by default.** Queues have no retries, dead-letter queue or consumer API. There is no tracing. No outbound webhooks, no feature flags.

## Suggested order

**Wave 0: security blockers (do first).** 15, 16, 18, the serving half of 17, and the "fix now" half of 20. Together they close the reproduced chain and turn CI green. Then 22, so the fixes stay fixed, followed by 19, 23, 21 and the strict-CSP half of 17. Until Wave 0 ships, deploy only on a private network (see "Recommended immediate mitigations" in the review).

**Wave 1: foundations (P0).** 02, 06 and 08 can run in parallel. Each removes a blocker for later work: 02 unblocks every AI feature and semantic search Phase 2; 06 gives agentic workflows and webhooks durable retries; 08 makes everything after it easier to use and to review. 03 starts as soon as the common MCP core lands.

**Wave 2: what engineers will notice (P1).** 05, 04, 10, 11, 09, 07. The knowledge service and agentic workflows are the headline AI features. OpenAPI, the test kit and the CLI are the developer-experience multipliers.

**Wave 3: completeness (P2).** 12, 13, 14.

**Before any of this:** fix the 8 high and 3 critical production advisories found on 2026-11-12. The CI audit gate failed until they were fixed. (Done in Phase 0, 2026-11-13: see feature 20 and [Roadmap.md](../Roadmap.md).)

## Principles for every feature

- **Same shape as the rest of the framework.** A service factory, providers chosen by name, routes with Swagger docs, a dashboard, analytics with `destroy()`, events on the shared emitter.
- **Memory provider first.** Every feature works offline with no keys and no infrastructure, so tests and first runs need nothing.
- **No new mandatory dependencies.** Heavy integrations (OpenTelemetry SDK, MCP transports) stay optional or live in `nooblyjs-ai-common`, which keeps its zero-dependency rule.
- **Safe by default.** Anything that lets an agent or a remote caller act (MCP tools, workflow tools, webhooks) is off until enabled, scoped by role and audited.
